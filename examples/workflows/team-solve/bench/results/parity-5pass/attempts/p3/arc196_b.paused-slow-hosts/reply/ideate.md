### NOTES
The key modeling step is to replace tile rotations by binary variables on the shared edges of the torus: one variable for each horizontal adjacency between neighboring cells and one for each vertical adjacency. A variable is 1 exactly when the line segment has an endpoint on that shared edge, which is equivalent to both neighboring tiles having endpoints there. With this representation, the no-dead-end condition is built in automatically.

Each tile type then becomes a small set of XOR constraints over GF(2). For an A cell, exactly one of its two horizontal incident edge variables must be 1, and exactly one of its two vertical incident edge variables must be 1. For a B cell, its two horizontal variables must be equal, its two vertical variables must be equal, and the horizontal value must differ from the vertical value. Therefore the whole problem is an affine linear system over GF(2), so the number of valid placements is either 0 or a power of 2.

The core difficulty is global consistency on the torus. Horizontal constraints around each row force the number of A cells in every row to be even; otherwise the horizontal edge variables cannot be assigned consistently around the cycle. Similarly, every column must contain an even number of A cells. After these parity conditions are satisfied, each row contributes one free bit determining its horizontal edge variables, and each column contributes one free bit determining its vertical edge variables. B cells then impose XOR equations between the corresponding row bit and column bit. Thus the remaining counting problem is to count assignments to row and column bits satisfying a signed bipartite graph of B-cell constraints.

Major pitfalls include off-by-one errors in prefix parities on the torus, especially deciding whether the current cell’s A has already been included in the prefix used for a B constraint. Another pitfall is forgetting that isolated rows and columns still contribute free bits, so the exponent is the number of connected components in the B-cell graph, including isolated vertices. A third pitfall is performance: the total grid size is up to 10^6 and T can be as large as 10^5, so the algorithm must be nearly linear, use fast input, and avoid heavy per-test overhead. A fourth pitfall is using a general-purpose method that is too slow or memory-heavy in Python, such as dense linear algebra or a very large direct constraint graph, when the structure can be exploited.

### NEXT
- Row/column elimination plus parity DSU on a signed bipartite graph: check that every row and every column has an even number of A cells; introduce one bit per row and one bit per column; for each B cell add an XOR equation between its row bit and column bit with a constant derived from the parity of A cells to the left and above; use a parity union-find to detect contradictions and count connected components; answer is 2 to the number of components if consistent. Pitfalls: prefix parity off-by-one on the torus, updating column parity before or after processing the current cell, counting isolated row/column vertices, and keeping memory and initialization fast across many test cases.

- Direct parity DSU on all edge variables: create one variable for every horizontal adjacency and one for every vertical adjacency; for each cell add local XOR equations encoding whether it is A or B; count connected components of the resulting constraint graph. Pitfalls: this uses up to twice as many variables as the row/column reduction and adds more redundant constraints, so it may be slower and more memory-intensive in Python; edge indexing around the torus is still error-prone; if dimensions of size 1 were allowed, self-adjacency would need special care.

- Sparse linear algebra over GF(2): formulate the entire affine system as a sparse matrix with constants, compute its rank and consistency, and return 2 to the nullity if consistent. Pitfalls: generic sparse elimination can suffer from fill-in and is difficult to implement efficiently in Python at this scale; it is likely overkill compared with union-find; consistency with the constant vector must be handled separately; the approach may not meet time limits unless it exploits the grid structure heavily.

- Transfer-matrix dynamic programming over the smaller dimension: process the grid row by row or column by column, keeping as state the assignment of edge variables crossing the frontier; enforce local tile constraints as cells are added; close the torus by ensuring the final state matches the initial state. Pitfalls: the state space is exponential in the smaller of H and W, so this is only viable when one dimension is very small; torus wraparound makes the DP more complicated because the first row or column state must be remembered or handled by cycle consistency; memory and time blow up for roughly square grids.

- Cycle-cover or perfect-matching reduction: interpret valid placements as 2-regular subgraphs or cycle covers of the toroidal grid with local gadgets enforcing A-turn and B-straight behavior, then count them using a Pfaffian or Kasteleyn-type determinant. Pitfalls: the torus is non-planar and requires careful sector/sign handling; constructing correct gadgets for A and B tiles is subtle; determinant-based methods are much heavier than the linear XOR structure suggests; this approach is likely far more complex than necessary and may be slower in practice.
