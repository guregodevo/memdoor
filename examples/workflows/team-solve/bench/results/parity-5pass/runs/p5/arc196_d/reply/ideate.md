### NOTES
The natural state to reason about is the array of prefix sums of road strengths. If the prefix value at town boundary \(i\) is \(P_i\), then a person from \(S\) to \(T\) becomes an interval \([l,r]\) with \(l=\min(S,T)-1\), \(r=\max(S,T)-1\), plus a sign: rightward if \(S<T\), leftward if \(S>T\). The requirement is that \(P_l=P_r\), and every intermediate prefix value \(P_x\) for \(l<x<r\) is strictly greater than \(P_l\) for a rightward person, or strictly less than \(P_l\) for a leftward person. Thus each person imposes equalities and strict unit inequalities on prefix variables.

This is a difference-constraint feasibility problem. Since road strengths may be negative and unbounded, feasibility is equivalent to the absence of a positive-weight cycle after contracting equality constraints. The important structural fact is that, because all constraints come from intervals on a line, any infeasibility can be witnessed by a forbidden pair of people. The forbidden pairs are: identical interval with opposite signs; same left endpoint but different right endpoints; same right endpoint but different left endpoints; and crossing intervals with the same sign. If this pairwise characterization holds, then a subset of people is feasible exactly when it contains no forbidden pair.

Once the problem is reduced to forbidden pairs, queries become easy in principle. If \(bad[j]\) is the largest index \(i<j\) such that people \(i\) and \(j\) form a forbidden pair, then a query \([L,R]\) is feasible iff the maximum of \(bad[j]\) over \(j\le R\) is smaller than \(L\). This works because \(bad[j]<j\), so any value at least \(L\) automatically corresponds to a pair fully inside \([L,R]\).

The core difficulty is therefore computing \(bad[j]\) for all \(j\). The endpoint-based forbidden pairs are relatively easy with hash maps, but one must be careful to keep the best two distinct opposite endpoints for each left or right endpoint, not just the latest one. The hard part is same-sign crossing pairs. This is a two-dimensional offline problem coupled with the input order: for each interval \(j\), we need the largest earlier interval \(i\) whose endpoints interleave with \(j\) and whose sign is the same. Different algorithmic frameworks are possible here, and their tradeoffs matter a lot for Python.

Major pitfalls:
- The forbidden-pair lemma is the central correctness assumption. If longer cycles can exist without containing one of the listed pairs, all pair-based approaches fail.
- Off-by-one errors are likely: prefix indices are town minus one, and crossing/interior conditions are strict.
- Identical opposite-sign intervals must be handled separately from same-left/same-right conflicts to avoid double counting or missing them.
- For same-left or same-right conflicts, the latest previous interval may have the same opposite endpoint, so the second-best distinct endpoint is needed.
- Crossing computation is the performance bottleneck. CDQ, 2D range trees, sliding windows, and block decompositions have very different constants and memory behavior in Python.
- Sign matters: crossing is forbidden only for equal signs; opposite signs may cross.
- The query reduction using prefix maxima of \(bad\) is valid only if \(bad[j]\) stores the maximum previous conflicting index, not merely any previous conflict.

### NEXT
- Try the supplied forbidden-pair reduction with CDQ divide-and-conquer for crossing pairs: compute endpoint conflicts with hash maps, then for each sign run CDQ over person index; in each merge, treat left-half intervals as points and right-half intervals as queries, sweep by left endpoint, and use a segment tree over right endpoints for maximum index. Run the same procedure on mirrored coordinates to catch the other crossing orientation. Pitfalls: \(O(M\log^2 M)\) time, segment-tree clearing between CDQ levels, recursion overhead, and possible Python TLE if constants are high.

- Try a descending-index rectangle-reporting approach for crossing pairs: for each sign, process people from largest index to smallest while maintaining an active set of later-index people. A current interval \(p\) conflicts with active intervals \(q\) in the rectangle \(l_p<l_q<r_p\) and \(r_q>r_p\). Report and delete all such active \(q\), assigning \(p\) as their largest previous crossing. Implement the active set with a segment tree over left endpoints, where each leaf stores a max-heap of right endpoints and each internal node stores the maximum right endpoint in its subtree. Run again on mirrored coordinates for the symmetric crossing orientation. Pitfalls: strict bounds, inserting the current person only after querying, keeping leaf heaps and internal maxima consistent, memory for many leaf heaps, and remembering that this only handles crossing conflicts, not endpoint conflicts.

- Try a one-pass online 2D range-maximum structure for crossing pairs: process people in increasing index order, insert previous same-sign intervals as points \((l,r)\) with value equal to their index, and query two rectangles for the maximum previous index crossing the current interval. This can be done with a range tree or Fenwick tree of segment trees over compressed coordinates. Pitfalls: \(O(M\log^2 M)\) per query/update, large memory from 2D coordinate lists, max queries do not support inclusion-exclusion, and Python memory/time may be worse than CDQ or range-reporting.

- Try a sliding-window approach that computes, for each left endpoint \(L\), the smallest \(R\) such that \([L,R]\) is infeasible. Feasibility is monotone in \(R\), so a two-pointer scan is possible if we can maintain the total number of forbidden pairs under adding and removing people. Endpoint conflicts can be maintained with counters, while crossing conflicts require a dynamic 2D counting structure supporting insert/delete and rectangle counting. Pitfalls: dynamic deletions are harder than insert-only structures, endpoint conflicts can be double-counted if same-left and same-right contributions are added naively, and the total number of pointer moves times the update cost may be too high in Python.

- Try a sqrt/block decomposition over person indices: precompute conflict information between blocks, for example a block-pair matrix saying whether any forbidden pair exists between two blocks, and optionally per-person bitsets of blocks with which that person conflicts. Answer a query by checking full blocks using a 2D prefix-OR over the block matrix and scanning only the partial boundary blocks. Pitfalls: precomputation can be expensive, partial-block handling must cover all conflict types, block size tuning is delicate, and Python bitsets or dense matrices may still be too slow or memory-heavy if not carefully implemented.
