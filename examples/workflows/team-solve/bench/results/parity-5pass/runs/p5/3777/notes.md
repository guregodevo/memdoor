- **State split:** F0/F1 track all subsequences, including empty, by length parity and alternating sum; Z0/Z1 track non-empty zero-product subsequences; P0[p]/P1[p] track non-empty positive subsequences with exact product p in 1..limit. This cleanly separates product 0 from positive products.
- **Bitset encoding:** max_sum=12*n, offset=max_sum, size=2*max_sum+1, and bit offset+s represents sum s. Left shifts are masked; right shifts naturally drop out-of-range bits. If abs(k)>max_sum, no subsequence can have that alternating sum.
- **Positive transition:** for x>0, skipping keeps old states. Taking x flips parity: old even length adds +x, old odd length subtracts x. P multiplies product by x and keeps only q<=limit; singleton [x] is added when x<=limit. Z and F use the same parity/sum shift, but Z only extends existing zero-product states while F extends all states.
- **Zero transition:** for x=0, P is unchanged because taking zero destroys positive product. Z is seeded from old F, meaning the zero can be appended to any previous subsequence, including empty or over-limit positive prefixes. Old Z states also skip or take the zero. F becomes the union of old parities in both parities because zero can be skipped or taken without changing sum.
- **Why F is needed:** a zero can make product 0 from a previous subsequence whose positive product already exceeded limit. P is capped at limit and would miss those sums, so F preserves uncapped sum/parity feasibility for future zero seeding.
- **Why exact product:** for the same sum and parity, a smaller positive product may remain <=limit after future multiplications while a larger one cannot, so keeping only the maximum product per sum/parity is unsafe.
- **Answer extraction:** scan p from limit down to 1 and return the first p whose P0[p] or P1[p] contains the target bit. If none exists, return 0 if the target bit is in Z0 or Z1, otherwise -1. The empty subsequence is never represented in P or Z.
- **Testing:** the included guarded main runs the provided examples plus a few edge cases and 200 fixed-seed random brute-force cases with n<=12, values 0..12, k in [-20,20], and limit<=50. It exits 0 on success and prints mismatches if any occur.
- **Complexity:** n<=150, bitset length <=3601, active products <=limit<=5000. Each positive element performs O(active_products) big-int shifts/ORs; memory is O(limit * bitset_words + bitset_words), well within constraints.
