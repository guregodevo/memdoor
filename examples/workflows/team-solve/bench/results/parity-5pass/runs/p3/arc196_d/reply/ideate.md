### NOTES
The natural model is to introduce prefix potentials \(P_x\) for prefix positions \(x=0,\dots,N-1\), where town \(x+1\) corresponds to \(P_x\), and each road strength is the difference of adjacent potentials. For person \(i\), let \(l_i=\min(S_i,T_i)-1\), \(r_i=\max(S_i,T_i)-1\), and let the sign be positive if \(S_i<T_i\), negative if \(S_i>T_i\). The requirement becomes:
- \(P_{l_i}=P_{r_i}\);
- for every \(l_i<k<r_i\), if the sign is positive then \(P_k>P_{l_i}\), and if the sign is negative then \(P_k<P_{l_i}\).

Thus a set of people is feasible exactly when the directed graph of strict inequalities, after contracting equal endpoint potentials, has no directed cycle. If it is acyclic, integer potentials can be assigned by topological ordering and then shifted so that \(P_0=0\).

The core difficulty is not checking one set of constraints, but answering many contiguous-range queries over the \(M\) people. The supplied plan hinges on a pairwise characterization: a set is infeasible iff it contains one of a few forbidden pairs:
- two intervals with the same left endpoint but different right endpoints;
- two intervals with the same right endpoint but different left endpoints;
- the same interval with opposite signs;
- two same-sign intervals that cross, i.e. \(l_i<l_j<r_i<r_j\) or the symmetric case.

Each of these pairs creates an immediate contradiction between an equality and a strict inequality, or a two-cycle of strict inequalities. The main correctness risk is whether a longer cycle of inequalities can exist without containing one of these forbidden pairs. The interval geometry should prevent that, but this pairwise reduction is the key assumption to verify.

If the pairwise characterization is correct, then a query \([L,R]\) is “No” exactly when the index interval \([L,R]\) contains a forbidden pair. Then it suffices to compute, for each person index, the smallest later index that forms a forbidden pair with it, or equivalently the largest earlier index that forms a forbidden pair with it. Shared-endpoint conflicts are easy using next/last occurrence arrays. The nontrivial part is computing the nearest same-sign crossing partner among up to \(2\times10^5\) intervals. This is a 2D geometric problem with strict open rectangles and sign separation. Opposite-sign crossings are not conflicts, same-sign nested intervals are not conflicts, and touching at a right-left endpoint is not a conflict, while sharing a left-left or right-right endpoint is a conflict. Any data structure must respect these strict distinctions.

### NEXT
- Implement the supplied plan as an online range-reporting sweep. For each sign separately, scan people in input order and keep only previous intervals that have not yet been assigned a crossing partner. Maintain two reporting structures: one keyed by right endpoint with the minimum left endpoint in each node and a min-heap of left endpoints at leaves, and one keyed by left endpoint with the maximum right endpoint in each node and a max-heap of right endpoints at leaves. For the current interval, query the right-keyed structure over the open right-endpoint range and report/delete all entries whose left endpoint is smaller than the current left endpoint; query the left-keyed structure over the open left-endpoint range and report/delete all entries whose right endpoint is larger than the current right endpoint. Each reported interval receives the current index as its earliest crossing partner. Combine these partners with next occurrences of the same left or right endpoint, then take suffix minima to answer queries. Pitfalls: strict open ranges, sign separation, lazy deletion across the two structures, updating node extrema after deletions, memory for many leaf heaps, and ensuring each tree descent is charged to a reported or lazily removed interval so the total work stays near \(O(M\log N)\).

- Use CDQ divide-and-conquer over the person index to compute, for each right endpoint \(j\), the largest earlier index \(i\) forming a bad pair. Handle same-left and same-right endpoint conflicts with a linear last-occurrence pass. In each CDQ cross step, for each sign, process the two crossing orientations with one-dimensional sweeps: for the case where the left-half interval starts before the right-half interval, sort left intervals by left endpoint and right queries by left endpoint, add left intervals to a Fenwick tree over right endpoints storing the maximum index, and query the open right-endpoint interval; for the case where the left-half interval starts inside the right-half interval, sort by right endpoint descending and use a Fenwick tree over left endpoints. Take the maximum over all cross steps, then use prefix maxima to answer queries. Pitfalls: \(O(M\log M\log N)\) time, possible extra log factor from sorting at every node, clearing Fenwick trees efficiently, strict inequalities, recursion overhead, and Python performance.

- Scan people backwards and use a true 2D range-minimum structure. For each sign separately, insert later intervals as points \((l,r)\) with value equal to their index. For the current interval, query the minimum index in the rectangle \(l\) in \((l_i,r_i)\) and \(r>r_i\), and also in the rectangle \(r\) in \((l_i,r_i)\) and \(l<l_i\). A segment tree over one coordinate with a Fenwick tree or segment tree over the other coordinate, storing minimum index and using offline coordinate compression, can answer these queries. Combine the results with next same-endpoint occurrences and suffix minima. Pitfalls: large memory \(O(M\log N)\), minimum is not invertible so a segment tree over the first coordinate is usually needed, two structures or separate sign runs, and \(O(M\log^2 N)\) time may be heavy in Python.

- Use parallel binary search on the earliest bad partner. For a batch of midpoints, insert all people up to each midpoint into a 2D range-maximum structure that stores the maximum index in a rectangle. For each left index, check whether any same-sign crossing interval with index greater than the left index exists in the two crossing rectangles, and also check shared-endpoint conflicts. Iterate until the answers converge. Pitfalls: conceptually simple but high complexity, repeated rebuilding or complex offline processing, still requires a 2D structure, and likely slower than direct nearest-partner methods.

- Use Mo’s algorithm over query ranges, maintaining the active set of people and a dynamic conflict detector. Shared-endpoint conflicts are easy with counts of left endpoints, right endpoints, and signed intervals. For same-sign crossing, maintain per-sign dynamic interval structures, for example segment trees over left endpoints with maximum right endpoint and over right endpoints with minimum left endpoint, augmented with heaps or other deletion-capable structures, that can tell whether any two active intervals cross. Pitfalls: \(O((M+Q)\sqrt M\log N)\) is probably too slow, deletions make exact crossing detection difficult, and the high constant may be prohibitive.

- Before committing to a scalable method, run a small brute-force verifier: enumerate all pairs in a range, test the bad-pair conditions, and compare with direct feasibility by building the equality/inequality graph for tiny \(N\) and \(M\). This validates the pairwise characterization and the query reduction, and provides an oracle for the final implementation. Pitfalls: it is only useful for small random tests and is not a scalable solution.
