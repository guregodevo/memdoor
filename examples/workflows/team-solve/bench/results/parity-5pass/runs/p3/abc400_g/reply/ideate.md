### NOTES
The core difficulty is the combination of a global cardinality constraint (exactly K disjoint pairs) with a pair weight that is the maximum of three additive terms. The key reduction is to stop thinking about the actual pairings and instead color each selected cake by one of the three attributes. For any feasible pairing, color both cakes in a pair by an attribute that attains the pair's maximum. Then each color class consists of whole pairs, so each color is used an even number of times, and the total price is exactly the sum of the colored attribute values. Conversely, any selection of 2K cakes colored X/Y/Z with each color used an even number of times can be paired inside each color, and the true price of each same-color pair is at least the sum of that color's values. Therefore the original maximum equals the maximum over such even-parity colored selections.

After this reduction, the problem becomes: for each cake choose none, X, Y, or Z; gain the corresponding attribute value; require exactly 2K chosen cakes; require the three color counts to be even. A direct DP over parity and count is O(N K 8), which is too large for the worst case. The parity dimension is only 8, so the natural exact method is to relax the exact count with a Lagrangian penalty and rely on concavity of the optimal value as a function of the number of pairs.

The supplied plan is therefore the most promising approach. Binary search an integer penalty P per pair. Double all attribute values and subtract P from every chosen cake, so a pair of two chosen cakes loses 2P in doubled scale, which corresponds to losing P in the original scale. For fixed P, an 8-state DP over parity masks computes the best doubled adjusted value and, among equal adjusted values, the maximum number of chosen cakes. If the value function F(k) is concave (this is the maximum-weight k-matching value function, equivalently an M-concave parity-assignment family), the largest P for which the DP returns at least 2K chosen cakes gives the answer by (dp_value + P * 2K) // 2. The complexity is about 31 * N * 24 state transitions over all test cases.

Important pitfalls for this approach: concavity must be true; otherwise the Aliens trick returns only the concave envelope. The scaling by 2 and the per-cake penalty are easy to mix up, and the final division by 2 must be exact. Tie-breaking must prefer the larger chosen count when adjusted values are equal; otherwise the binary-search predicate is not the correct one. The high penalty bound must be infeasible, for example one more than the maximum possible pair price. Negative adjusted gains cannot be discarded, because a few negative items may be needed to fix parity while keeping many positive items. Implementation performance matters: roughly 75 million state updates for total N = 100000, so naive tuple/list DP may be slow. Use fresh state arrays per item to avoid using the same cake multiple times, keep state updates unrolled or very tight, and consider hybrid exact DP for very small K or very small N - 2K.

Other candidate directions have different tradeoffs. Exact count DP or complement DP is straightforward and avoids concavity, but is quadratic in the worst case. A quota-based min-cost flow formulation fixes even quotas for X, Y, Z and an unselected quota, reducing to a 4-color assignment, but optimizing over quotas or doing a 2D Lagrangian search is complex and generic flow is too slow. A slope-trick or max-plus concave-sequence DP could avoid binary search, but intermediate parity-state functions may not be ordinary concave sequences, and the implementation is delicate. Greedy or sparse-candidate matching is tempting but not correct; for example, four cakes with values (100,99,0), (100,0,0), (0,99,0), (99,0,0) show that taking the best pair first gives 299 while the optimum is 198 + 199 = 397. General parametric blossom matching is theoretically related but far too slow for N = 100000.

### NEXT
- Implement the Aliens/WQS 8-state parity DP with doubled values, per-cake penalty, max-count tie-breaking, and binary search over P; use fast I/O and tight state updates.
- Add hybrid exact DP for small K and complement DP for small N - 2K to handle extremes faster and to cross-check the WQS result.
- Explore a quota-based 4-color assignment formulation with min-cost flow or 2D Lagrange multipliers as an alternative, but only if it can be made near-linear and tie/parity handling is robust.
- Investigate a slope-trick / max-plus representation of the 8 parity value functions to compute the K-th value directly, focusing on whether intermediate functions remain concave/M-concave.
- Test and likely discard greedy or sparse-candidate matching ideas using small counterexamples; consider them only if a provable sparse certificate can be found.
- Use small random brute-force matchings to validate the concavity assumption and the WQS answer formula before finalizing.
