### NOTES
The main difficulty is that each tile has only a few local rotations, but the no-dead-end rule couples every shared edge, and the torus wrap makes the coupling cyclic. A brute force over tile rotations is impossible. The useful observation is that if we put a binary variable on every grid edge indicating whether an endpoint lies on that edge, then the local tile types become very simple parity conditions. For an A tile, the two opposite pairs of edge variables must differ; for a B tile, the two opposite pairs must be equal and one of the adjacent pairs must differ. The global matching condition is exactly that the two variables on each shared edge are the same variable. Therefore the whole problem can be viewed as a system of XOR equations over binary variables.

The torus introduces cycle consistency: going around a row, the horizontal edge variables must return to their starting value, which forces the number of A tiles in that row to be even. Similarly each column must contain an even number of A tiles. If any row or column parity is odd, the answer is immediately zero. When all parities are even, the horizontal variables in a row are determined up to one free bit, and the vertical variables in a column are determined up to one free bit. The only remaining coupling is at B tiles, where the top edge variable and left edge variable must differ; this becomes one XOR equation between the corresponding row free bit and column free bit. Thus the counting problem can be reduced to counting parity assignments on a bipartite graph whose nodes are rows and columns and whose edges are B cells, with edge labels determined by prefix parities of A cells.

This suggests several possible algorithmic directions. The most direct is to solve the bipartite XOR system with a parity union-find or DFS. Other directions are more general or exponential and are useful mainly as fallbacks or for small dimensions.

Pitfalls common to the promising reduction: the prefix parity used in a B-cell label must be the parity before that cell in both the row and the column; column prefix parities must be updated only after the current row has used them; row and column parity checks must both be performed; isolated row/column nodes still contribute free bits; the DSU parity orientation must be handled carefully; and many small test cases require fast input and low per-case overhead.

### NEXT
- Try the parity/DSU reduction: maintain column prefix parities while scanning rows, add one signed edge for each B cell between its row node and column node, check row and column A-parities, and if consistent return 2 to the power of the number of connected components of the signed bipartite graph, modulo 998244353. Pitfalls: off-by-one in prefixes, updating column parities too early, forgetting isolated components, parity union-find sign errors, and memory/performance for many cases.
- Try a frontier dynamic programming or transfer-matrix approach: sweep one dimension and keep the bits on the frontier as state, applying local tile constraints row by row, then take the trace or fix the boundary state to handle the torus. Pitfalls: state size exponential in the frontier width, torus wrap requires a trace rather than a simple initial-to-final sum, and it is not viable when both dimensions are large even though HW is only 1e6.
- Try a general sparse linear-algebra approach over GF(2): build all XOR equations from the edge variables and compute the rank of the constraint matrix, with the answer 2 to the power of the nullity if consistent. Pitfalls: dense fill-in or cubic bitset complexity, much larger memory, and it ignores the special pairwise bipartite structure that makes union-find linear-time.
- Try a six-vertex / fully-packed-loop / dimer-model interpretation: view A tiles as forced turns and B tiles as forced straights, then attempt to count loop configurations using Pfaffian or tensor-network methods. Pitfalls: arbitrary fixed A/B patterns and torus boundary conditions may not fit standard Pfaffian formulas, winding sectors can be missed, and the implementation is far more complex than needed.
- Try a Fourier or inclusion-exclusion expansion over edge mismatches: enforce equality across shared edges using character sums and expand the product of local tile indicators. Pitfalls: the expansion can be exponential in the number of edges or cells, cancellations are subtle, and unless the XOR structure is exploited it will not meet the required linear-time bound.
