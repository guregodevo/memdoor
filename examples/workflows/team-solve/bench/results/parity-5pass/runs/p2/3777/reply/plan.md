### PLAN
Cap the alternating sum at ±12·n and encode reachable sums as integer bitsets with an offset, so shifts implement adding or subtracting a value. For positive products (subsequences with no zero), keep two lists indexed by product ≤ limit and length parity, each entry a sum bitset; process each nonzero x by copying the lists and updating product p to p·x only when p·x ≤ limit. Because choosing a zero after an over-limit positive product can still yield a valid product 0, maintain a separate four-bitset DP for parity and whether a zero has been chosen to detect product-0 subsequences. Use +x (left shift) when the current subsequence length is even and -x (right shift) when it is odd, and keep old copies to enforce each element is used at most once. Finally remove the empty state, scan products from limit down to 1 for the target sum, and return 0 if only the zero DP reaches the target, otherwise -1.

### TASKS
- Set `offset = 12 * len(nums)`, `mask = (1 << (2 * offset + 1)) - 1`, and `target = offset + k`; return `-1` immediately if `target` is outside `[0, 2 * offset]`.
- Implement positive-product DP: `even` and `odd` arrays of length `limit + 1` initialized with `even[1] = 1 << offset`; for each `x > 0`, copy both arrays and for `p = 1..limit // x` update `odd[p * x] |= (even[p] << x) & mask` and `even[p * x] |= odd[p] >> x`.
- Implement zero-product existence DP: four bitsets for `(even/odd, has_zero/no_zero)`, initialized with `even_no_zero = 1 << offset`; for each `x`, use old copies to flip parity, shift sums by `+x`/`-x`, and force `has_zero = True` when `x == 0`.
- Combine answers: clear the empty bit from positive `even[1]`, then scan `p` from `limit` down to `1` and return `p` if `(even[p] | odd[p])` has the target bit; otherwise return `0` if either `has_zero` bitset has the target bit, else `-1`.
- Verify edge cases: all zeros, `k = 0` with empty vs non-empty product `1`, zeros after products exceeding `limit`, and `limit = 1`.
