- **Potential model:** Let town potentials be P_1=0 and P_{v+1}=P_v+w_v. A person from S to T becomes an interval [l,r] with sign + if S<T and - if S>T. For +, need P_l=P_r and P_x>P_l for l<x<r. For -, need P_l=P_r and P_x<P_l for l<x<r.
- **Pairwise incompatibility:** A set is feasible iff it has no incompatible pair. Incompatible pairs are: same left endpoint, same right endpoint, or same-sign crossing intervals. Touching endpoints (r_j=l_i or r_i=l_j) are compatible. Same-sign containment and opposite-sign overlap/nesting are compatible.
- **Why pairwise is enough:** After contracting equal endpoint components, plus intervals create edges from their endpoint component to interior components, minus intervals create edges from interior components to their endpoint component. Opposite-sign edges always go from plus-side components to minus-side components. Same-sign edges follow strict containment direction. Touching chains cannot create a directed cycle under the no-same-side-endpoint and same-sign-laminar conditions, so strict inequalities are acyclic and integer potentials exist.
- **prev array:** For each person i, prev[i] is the largest j<i incompatible with i. A query [L,R] is Yes iff max_{i in [L,R]} prev[i] < L. Endpoint conflicts are found by scanning with last_left and last_right.
- **Same-sign crossing implementation:** Instead of CDQ, use block bitsets for Python performance. For each sign, process its indices in increasing original order in blocks of size B=3072.
- **Block data:** For each block, store prefix bitsets by left endpoint and by right endpoint, count arrays for left/right endpoints, and sparse tables: max right over left-sorted ranges and min left over right-sorted ranges. These sparse tables give exact existence of a crossing candidate in O(1).
- **Crossing conditions:** Type A: l_j <= l_i, r_j > l_i, r_j <= r_i. Type B: l_j >= l_i, l_j < r_i, r_j >= r_i. These relaxed forms include same-left/same-right conflicts but exclude touching endpoints.
- **Querying a person:** First check the same block using a mask of earlier local positions. Then scan earlier blocks from newest to oldest. For each block, use sparse-table existence checks; only if a candidate exists, compute the actual bitset union of type A and type B and take the highest set bit. If the current prev lies inside a scanned block, mask to indices greater than prev.
- **Complexity:** Build is O((M/B)N + M log B). Scanning earlier blocks is O(M^2/B) existence checks; with M=2e5 and B=3072 this is about 6.5 million checks. Big-int bitset operations are performed only when a candidate exists, so they are O(M) in practice.
- **Pitfalls:** Strictness matters for touching endpoints. Same left/right are conflicts, but r_j=l_i or l_j=r_i are not. When both type A and type B exist, their bitsets must be ORed before taking the latest index. Count arrays use unsigned short because block size is below 65535.
