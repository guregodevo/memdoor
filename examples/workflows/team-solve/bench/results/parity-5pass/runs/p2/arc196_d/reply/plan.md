### PLAN
Convert each person into a directed interval \([l,r]\) with sign \(+\) if \(S<T\) and \(-\) if \(S>T\). Road strengths can be viewed as prefix potentials, so each person requires equal endpoint potentials and all interior potentials strictly above (for \(+\)) or strictly below (for \(-\)) the endpoint value. A set of people is feasible iff it contains no pairwise incompatible pair: same-sign intervals must be laminar, i.e. they conflict exactly when their interiors overlap and neither strictly contains the other; opposite-sign intervals conflict exactly when they share a left endpoint or a right endpoint. Thus a query \([L,R]\) is feasible iff no incompatible pair lies inside it, which can be checked by computing for each index \(i\) the largest previous index `prev[i]` incompatible with \(i\), then answering Yes iff \(\max_{i\in[L,R]} prev[i] < L\). Compute `prev` offline with CDQ divide-and-conquer over person indices: in each merge step, left-half indices are earlier than right-half indices, and conflicts can be found using endpoint arrays plus two monotone sweeps with a range-update/point-query maximum segment tree. Finally, answer all queries with a range-maximum structure over `prev`.

### TASKS
- Parse the input, normalize each person to \((l,r,dir)\), store all queries, and implement the \(O(1)\) pairwise incompatibility predicate for base cases and validation.
- Implement a CDQ divide-and-conquer over person indices with a small brute-force threshold; for each recursive segment maintain two lists of indices sorted by \(l\) ascending and by \(r\) descending for the sweep steps.
- In the CDQ cross step, update `prev` for right-half indices using left-half endpoint maxima for same-direction same-\(l\) conflicts and opposite-direction same-\(l\) or same-\(r\) conflicts.
- Implement the two same-direction crossing sweeps: one sorted by \(r\) adding left intervals with \(r_j \le r_i\) and range-updating \((l_j+1, r_j-1)\) then point-querying at \(l_i\); the other sorted by \(l\) descending adding left intervals with \(l_j > l_i\) and range-updating \((l_j+1, r_j)\) then point-querying at \(r_i\), using separate max segment trees for the two directions and efficient clearing.
- After computing `prev`, build an iterative range-maximum segment tree or sparse table over it and output Yes/No for each query based on whether the range maximum is less than the query’s left endpoint.
