# team-solve-v2

A team of fresh contexts solves any prompt: `task.md` in a folder, a program or a document out, checked before the run passes. The method is [GVS5H](https://github.com/slee-persis/GVS5H)'s, whose five Qwen3.8-27B models match Fable 5 on LiveCodeBench Hard; the published runs of that result are the `team-solve` example, kept as they were ([examples/workflows/team-solve](../../examples/workflows/team-solve/)). v2 is the same team on any task, on any model.

`problem` reads `task.md`; an empty folder gets the sample problem. `plan` names the deliverable on the first line of `plan.md`, `solution.py` for a program or `answer.md` for a document, lists the requirements, and starts `notes.md`, the ledger. `ideate-a` and `ideate-b`, in parallel, each add a proposal to the ledger. `solve` writes the deliverable. `test` runs every `tests/N.in` through the program and diffs against `tests/N.out`; with no samples it records that the reviewer judges. `review` writes `review.md`, `verdict: PASS` or `verdict: FAIL` first, and the repair instructions; `repair` is one fresh worker on them. `judge` runs only without samples: a fresh context that reads `task.md` and the deliverable alone writes `verdict.md`. `verify` fails the run when a sample differs or the verdict is FAIL. Each role starts from nothing and reads only the files on disk.

Run it in a folder with `task.md`, and for a program the paired `tests/N.in` / `tests/N.out` files: `memdoor workflow run team-solve-v2 --wait`, exit 0 when the check passes. `--model <id>` puts every step on one model, an id `memdoor model search` shows; without it, the `/model` pin, else the agent's ladder. It leaves `plan.md`, `notes.md`, the deliverable, `review.md`, `verdict.md` without samples, and the check logs. Needs Python 3, bash and diff.

With no key, `memdoor connect local` connects Ollama, llama.cpp, vLLM or LM Studio on this machine ([how](https://memdoor.ai/docs/providers#a-local-runtime-no-key)). Ollama reads a prompt through a 4,096-token window unless told otherwise, and a role's prompt is longer than that: start it with `OLLAMA_CONTEXT_LENGTH=32768`, or make a tag with `PARAMETER num_ctx 32768` and pin that one. A hard problem is about 300K output tokens through the loop, an hour or more on a home machine, as a background job.
