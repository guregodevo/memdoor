# fix-tests

Makes a failing test suite pass by fixing the code, and leaves the fix in the working tree to review and commit.

`detect` finds the project's test command — `$MEMDOOR_TEST_COMMAND` when set, else `go test ./...` (go.mod), `cargo test` (Cargo.toml), `npm test` (a test script in package.json), `python3 -m pytest` (pyproject.toml, setup.py, pytest.ini; `python` when there is no `python3`) or `make test` (a test target) — and writes it to `.memdoor/runs/fix-tests-<partition>.sh`. `fix` is skipped when that command already passes; otherwise the coder reads the failure, fixes the code under test (a test only when the test itself is wrong, and it says why), and reruns until the command passes — its target. `report` writes `.memdoor/runs/fix-tests-<partition>.md`: the cause, the change, the diff. Nothing is committed or pushed. Run it with `memdoor workflow run fix-tests --wait`, or in GitHub Actions after the steps that install the project's dependencies, with `uses: guregodevo/memdoor-action@v1` and `workflow: fix-tests`. Needs a model on your key.
