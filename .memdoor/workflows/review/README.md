# review

The review loop as a DAG: `review` reads one commit with the `review` skill — every finding cites file:line and is verified by running, then the untouched files are swept for the same class of claim — and writes `.memdoor/runs/REVIEW-<commit>.md`; the run stops at a gate for you to read it; `fix` applies what the review marks **must fix**, runs build, vet and the suite, and commits with a message that says why; `check` reruns vet and the suite on the result. The partition is the commit: `/workflow:review` then the commit (`--partition abc1234`); with no commit it reviews HEAD. Approve the gate with `a` in `/workflow` or `memdoor workflow approve <run> approve`; a review with nothing to fix is approved the same way and `fix` says so. Needs a model on your key; leaves the review under `.memdoor/runs/` and, when there was something to fix, a commit.
